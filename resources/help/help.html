PhotoLife Help

PhotoLife builds a catalogue alongside your nature-photo library and hangs each photo on the tree of life. It never moves, renames or edits your files — it reads them and keeps its own database.

The workflow at a glance

  1. Add a folder of photos to the library → PhotoLife scans it.
  2. Build a reference tree for a group and region (e.g. Orchids of Victoria) from iNaturalist.
  3. Import a checklist CSV to add rare species and conservation status (optional).
  4. Match Library → every photo is tied to a taxon by its folder and file name.
  5. Review the ones PhotoLife was unsure about.
  6. Browse the tree and watch your coverage grow.

Steps 2–4 need an internet connection (they query the iNaturalist API); everything is cached, so afterwards PhotoLife works offline.

1. Add your photo folders

File → Add Folder to Library… and choose a folder. PhotoLife walks it, records every image, and groups a RAW file and its same-name JPEG as one capture. It skips junk (Thumbs.db, sidecar files, folders like “To Sort and Upload”).

It watches your folders afterwards and re-scans automatically when they change. File → Rescan Library forces a full re-scan; unchanged files are never re-read.

Your folder names matter: a Family / Genus / Species tree with scientific names in the file names matches best, but PhotoLife copes with synonyms, misspellings, sp., hybrids, aggregates, and common-name folders for fauna.

2. Build a reference tree

File → New Reference Tree… Give it a name, a root taxon (Orchidaceae), an optional rank, and a region (Victoria, AU — leave blank for worldwide). PhotoLife resolves the place and taxon against iNaturalist, pulls the region’s species list, and fills in the intermediate ranks so the tree is connected from kingdom down to species.

You can keep several trees and switch between them with the drop-down at the top of the Reference Trees panel on the left. File → Refresh Reference Tree re-pulls the current one from iNaturalist.

The Search taxa box under the drop-down jumps the tree to a taxon as you type — matching its scientific or common name — and press Enter to step through the other matches. If the right pane is on the Browse tab it follows along, showing that taxon’s photos. A match hidden by the “photographed only” filter un-hides it.

3. Import a regional checklist

File → Import Checklist… and pick a CSV of <name>,<conservation status> rows (such as a state vascular-plant list). PhotoLife adds any species in the current tree’s genera — including rarities with no iNaturalist observations — and records their threat status, which then shows in the coverage panel and the tree tooltips.

4. Match your photos

File → Match Library. For each capture PhotoLife parses the folder path and the file name, reconciles them against the cached taxonomy (including synonyms), scores the result, and either applies it automatically or puts it in the review queue. Re-running Match never disturbs a decision you made yourself.

In the All Photos tab a coloured dot on each thumbnail shows its status: ● automatic, ● needs review, ● unmatched, ● confirmed by you. The Show box filters by status.

5. Review the uncertain matches

The Review tab lists everything PhotoLife was unsure about, ordered by folder. Type in the Filter photos box at the top of the list to narrow it to photos whose name, folder or guess matches — handy for working one genus at a time. For the selected photo you see its guess, a ranked list of alternatives, and a taxon search box. Then:

  • Confirm — accept the highlighted taxon. PhotoLife learns the name, so the same oddity is never queued again.
  • Reject — there is no good match; drop it from the queue.
  • Genus only — tie it to the genus (for sp. photos).
  • Not a taxon — this folder is a place or a staging folder, not a species.
  • Skip — come back to it later.
  • Apply to folder — give the chosen taxon to every remaining pending photo in the same folder.

Browsing & coverage

The Browse tab follows your selection in the tree: pick a taxon and you see its cover photo, its details, and a grid of just its photos. The Coverage column in the tree shows a ✔ for photographed species, a · for missing ones, and a “have / total” count on genera and families.

The panel under the tree summarises the whole project: species photographed, threatened-species coverage broken out by status, and the most recent capture. The Missing Species tab is a plain list of the gaps — activate one to jump to it in the tree.

The Only taxa I’ve photographed checkbox above the tree collapses it to just the branches you have a photo somewhere in — a quick “what have I got” view. Untick it to see the whole reference tree again.

The image viewer

Double-click any thumbnail to open the full-size viewer. Left/Right (or Page Up/Down) move through the current set, Home/End jump to the ends, and Esc closes it.

Learned names

File → Learned Names… lists the corrections PhotoLife has picked up from your reviewing. Forgetting one puts the affected photos back in the queue on the next Match Library run.

Where PhotoLife keeps things

The catalogue database and the thumbnail cache live in your user data folder (~/.local/share/PhotoLife on Linux, %LOCALAPPDATA%\PhotoLife on Windows). Your original photos are never touched. Deleting that folder resets PhotoLife without affecting a single photo.

RAW files

When a shot has both a RAW and a JPEG, PhotoLife shows the JPEG. For a RAW with no JPEG sibling it reads the embedded preview — if this build was compiled with LibRaw. Otherwise a RAW-only capture shows a plain placeholder tile; the photo is still fully catalogued and matched.

Command line

For scripting and first-time bulk imports, the same steps are available headless:

PhotoLife --scan <folder>
PhotoLife --build-project "<name>" --taxon <taxon> --rank <rank> --place "<region>"
PhotoLife --import-checklist <file.csv> --into "<project>" --source "<label>"
PhotoLife --match

PhotoLife — taxonomy and species lists from the iNaturalist API; read-only catalogue.
