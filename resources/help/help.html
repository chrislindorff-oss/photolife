PhotoLife Help

PhotoLife builds a catalogue alongside your nature-photo library and hangs each photo on the tree of life. It never moves, renames or edits your files — it reads them and keeps its own database.

The workflow at a glance

  1. Add a folder of photos to the library → PhotoLife scans it.
  2. Build a reference tree for a group and region (e.g. Orchids of Victoria) from iNaturalist.
  3. Import a checklist CSV to add rare species and conservation status (optional).
  4. Match Library → every photo is tied to a taxon by its folder and file name.
  5. Review the ones PhotoLife was unsure about.
  6. Browse the tree and watch your coverage grow.

Steps 2–4 need an internet connection (they query the iNaturalist API); everything is cached, so afterwards PhotoLife works offline.

Finding your way around

The toolbar (and the View menu) has three mutually-exclusive modes:

  • Reference Tree — the default. The tab row underneath shows Photos of Tree Selection, Map, Missing Taxa, Reference Photos and My Best Shots — all of them scoped to whatever taxon or reference tree you have selected on the left.
  • All Library Photos — every photo in the catalogue, regardless of any reference tree. This is where the Show status filter and the right-click photo menu live.
  • Review Unmatched — the review queue (see below). Its count badge shows how many photos are waiting.

The Reference Trees panel on the left (search box, tree, coverage summary) stays visible no matter which mode you're in, so you can still search or select a taxon while reviewing or browsing the whole library.

1. Add your photo folders

File → Add Folder to Library… and choose a folder. PhotoLife walks it, records every image, and groups a RAW file and its same-name JPEG as one capture. It skips junk (Thumbs.db, sidecar files, folders like “To Sort and Upload”).

It watches your folders afterwards and re-scans automatically when they change. File → Rescan Library forces a full re-scan; unchanged files are never re-read. File → Remove Photos With Missing Files… finds catalogued photos whose file has since vanished (moved or deleted outside PhotoLife) and lets you drop them from the catalogue.

Your folder names matter: a Family / Genus / Species tree with scientific names in the file names matches best, but PhotoLife copes with synonyms, misspellings, sp., hybrids, aggregates, and common-name folders for fauna.

2. Build a reference tree

File → New Reference Tree… Give it a name, a root taxon (Orchidaceae), an optional rank, and a region (Victoria, AU — leave blank for worldwide). PhotoLife looks up the place and taxon on iNaturalist and asks you to confirm the exact match for each before building — useful when a name is ambiguous. Once confirmed, it pulls the region’s species list and fills in the intermediate ranks so the tree is connected from kingdom down to species.

You can keep several trees and switch between them with the drop-down at the top of the Reference Trees panel on the left. File → Refresh Reference Tree re-pulls the current one from iNaturalist; File → Delete Reference Tree… removes one you no longer need (your photos and their matches are untouched).

File → Fetch Subspecies/Varieties… checks the current tree’s species (or, from the tree’s right-click menu, just one branch) for iNaturalist subspecies, varieties and hybrids iNat’s regular species list doesn’t report on its own — it makes a few requests per species, so it can be slow for a large branch, but it's safe to quit and re-run later.

The Search taxa box under the drop-down jumps the tree to a taxon as you type — matching its scientific or common name — and press Enter to step through the other matches. If the right pane is on Photos of Tree Selection it follows along, showing that taxon’s photos. A match hidden by the “photographed only” filter un-hides it. The Ranks… button lets you hide ranks you don't care to see in the tree (e.g. collapse straight to species, skipping family/genus rows).

3. Import a regional checklist

File → Import Checklist… and pick a CSV of <name>,<conservation status> rows (such as a state vascular-plant list). PhotoLife adds any species in the current tree’s genera — including rarities with no iNaturalist observations — and records their threat status, which then shows in the coverage panel and the tree tooltips.

4. Match your photos

File → Match Library. For each capture PhotoLife parses the folder path and the file name, reconciles them against the cached taxonomy (including synonyms), scores the result, and either applies it automatically or puts it in the review queue. Re-running Match never disturbs a decision you made yourself.

Switch to the All Library Photos view to see every photo regardless of reference tree. A coloured dot on each thumbnail shows its status: ● automatic, ● needs review, ● unmatched, ● confirmed by you. The Show box in the toolbar filters by status, and Display… lets you choose which fields (name, matched taxon, date, filename, file type) appear under each thumbnail. Right-click a photo (here or in any other grid) for a context menu — open it in your file manager, star or unstar it as a best shot, or remove it from the catalogue.

5. Review the uncertain matches

Switch to the Review Unmatched view. The list on the left shows everything PhotoLife was unsure about, grouped by matching name; Collapse all/Expand all and the Filter photos box (by name, folder or guess) help you work one genus at a time. For the selected photo you see it side-by-side with an iNaturalist reference photo of the highlighted candidate, the engine’s guess, a ranked list of alternatives, and a taxon search box. Then:

  • Confirm — accept the highlighted taxon. PhotoLife learns the name, so the same oddity is never queued again.
  • Reject — there is no good match; drop it from the queue.
  • Genus only — tie it to the genus (for sp. photos).
  • Not a taxon — this folder is a place or a staging folder, not a species.
  • Skip — come back to it later.
  • Undo — reverses your last Confirm/Reject/Genus only/Not a taxon/“Use Selected Taxon on Tree” decision, putting that photo straight back in the queue. Only the last single-photo decision can be undone.
  • Use Selected Taxon on Tree — confirms the photo as whatever taxon is currently selected in the Reference Trees panel on the left, so you can browse the tree with one hand and confirm matches with the other.
  • Apply to folder — gives the chosen taxon to every remaining pending photo in the same folder. Tick Include subfolders first to extend that to the whole subtree. Always asks you to confirm how many photos will change before doing it.
  • Ignore Folder… — marks a folder (and its subfolders) as not containing taxa at all — a place name or a staging/miscellany folder — and drops every pending photo in it from the queue in one go.

Most of these have keyboard shortcuts — see Keyboard shortcuts — so you can work through a long queue without reaching for the mouse.

Browsing & coverage

The Photos of Tree Selection tab follows your selection in the tree: pick a taxon and you see its cover photo, its details, and a grid of just its photos (with a Reassign to Taxon… button if you need to move a batch of photos to a different species). The Coverage column in the tree shows a ✔ for photographed species, a · for missing ones, and a “have / total” count on genera and families.

The panel under the tree summarises the whole project: species photographed, threatened-species coverage broken out by status, and the most recent capture. The Missing Taxa tab is a plain list of the gaps, with its own filter box — activate an entry to jump to it in the tree.

The Only taxa I’ve photographed checkbox above the tree collapses it to just the branches you have a photo somewhere in — a quick “what have I got” view. Untick it to see the whole reference tree again.

Reference photos & best shots

The Reference Photos tab shows one iNaturalist photo per species in the current tree, for comparison while you're out identifying things. PhotoLife fetches missing ones automatically the first time you open the tab for a tree with gaps, or on demand via File → Fetch Reference Photos.

Right-click any of your own photos (in any grid) to star it as the Best Shot of its species — only available once the photo is identified. Starred photos get a gold star badge on their thumbnail and show up together in the My Best Shots tab. The full-size viewer also has an Add/Remove Best Shot button.

The map

The Map tab plots every geotagged photo in the current tree selection as a pin on an OpenStreetMap view, scoped exactly like Photos of Tree Selection. Drag to pan, scroll to zoom, and use Fit to Photos to frame everything in view — it does this automatically whenever you change the tree selection. Photos taken close together cluster into one pin showing a count; click a single-photo pin to open it, or a cluster to pick which of its photos to open. Only photos whose file carried GPS data appear here — look for the GEO badge on a thumbnail elsewhere in the app, or hover it for the exact coordinates.

The image viewer

Double-click any thumbnail to open the full-size viewer. Left/Right (or Page Up/Down) move through the current set, Home/End jump to the ends, and Esc closes it. If the photo has GPS data, a View on Map button opens its location in your browser.

Learned names

File → Learned Names… lists the corrections PhotoLife has picked up from your reviewing. Forgetting one puts the affected photos back in the queue on the next Match Library run.

Where PhotoLife keeps things

The catalogue database, thumbnail cache and map-tile cache live in your user data folder (~/.local/share/PhotoLife on Linux, %LOCALAPPDATA%\PhotoLife on Windows). Your original photos are never touched. Deleting that folder resets PhotoLife without affecting a single photo.

RAW files

When a shot has both a RAW and a JPEG, PhotoLife shows the JPEG. For a RAW with no JPEG sibling it reads the embedded preview — if this build was compiled with LibRaw. Otherwise a RAW-only capture shows a plain placeholder tile; the photo is still fully catalogued and matched.

If some of your RAW photos show up in the wrong place on the map, run File → Fix RAW Photo Locations… once — it corrects a since-fixed bug where a RAW file's GPS hemisphere (north/south, east/west) could be read incorrectly. It only re-reads location data; nothing else about your catalogue changes.

Command line

For scripting and first-time bulk imports, the same steps are available headless:

PhotoLife --scan <folder>
PhotoLife --build-project "<name>" --taxon <taxon> --rank <rank> --place "<region>"
PhotoLife --import-checklist <file.csv> --into "<project>" --source "<label>"
PhotoLife --match

PhotoLife — taxonomy and species lists from the iNaturalist API; map tiles from OpenStreetMap; read-only catalogue.
